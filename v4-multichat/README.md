# v4 — несколько веток разговора, свой стиль и скиллы на ветку (текущая версия)

Самая функциональная версия. Поверх [v3](../v3-persona-typing) добавлена система именованных веток разговора внутри одного Telegram-чата — по сути мини-аналог отдельных «чатов»/проектов, у каждого своя история, свой стиль общения и свой набор подключаемых скиллов.

## Что изменилось относительно v3

### Ветки разговора ("чаты")

Раньше один Telegram-чат = один непрерывный разговор с Claude. Теперь внутри одного Telegram-диалога можно вести несколько независимых веток — например, «работа» и «личное» — каждая со своей историей на диске (`sessions/<chat_id>/<имя_ветки>/`) и своим `session_id` Claude Code, так что переключение веток не путает контексты.

Команды:

| Команда | Действие |
|---|---|
| `/newchat <имя>` | создать новую ветку и переключиться на неё |
| `/chats` | список веток, активная отмечена стрелкой |
| `/switch <имя>` | переключиться на существующую ветку |
| `/rename <имя>` | переименовать текущую ветку (переносит и файлы на диске) |
| `/delchat <имя>` | удалить ветку (нельзя удалить активную — сначала `/switch`) |
| `/reset` | сбросить только историю текущей ветки |
| `/status` | показать активную ветку, её стиль и подключённые скиллы |

### Свой стиль общения на ветку

- `/style <текст>` — задать собственный системный промпт для текущей ветки (полностью заменяет дефолтный дружеский тон). Например, ветка «работа» может быть сухой и по делу, а «личное» — как раньше, неформальной.
- `/resetstyle` — вернуть ветку на дефолтный стиль (`CLAUDE_PERSONA` / встроенный `DEFAULT_PERSONA`).

### Скиллы — подключаемые пресеты поведения

Скиллы — это именованные фрагменты системного промпта, которые можно накидывать поверх стиля ветки. Хранятся в `skills.json` (по умолчанию в корне проекта), редактируются прямо текстом на сервере, без правки кода:

```json
{
  "программист": "Когда я спрашиваю про код — отвечай как опытный инженер...",
  "коротко": "Отвечай максимально коротко — 1-3 предложения...",
  "училка": "Объясняй как учитель терпеливому ученику...",
  "юморист": "Добавляй лёгкий юмор и иронию в ответы..."
}
```

Команды:

- `/skills` — список всех скиллов из `skills.json` с отметкой ✅/▫️, какие подключены к текущей ветке. Файл перечитывается при каждом вызове команды, так что новые скиллы подхватываются без перезапуска бота.
- `/addskill <имя>` — подключить скилл к текущей ветке (можно несколько одновременно, они складываются).
- `/removeskill <имя>` — отключить.

Итоговый системный промпт для каждого вызова Claude собирается как: `стиль ветки (свой или дефолтный) + тексты всех подключённых скиллов`.

### Внутреннее изменение: формат хранения состояния

Вместо плоского `sessions/_sessions.json` (chat_id → session_id) теперь используется `sessions/_state.json` с вложенной структурой на чат: активная ветка + словарь веток, в каждой — `session_id`, `persona`, список `skills`. При первом сообщении после обновления с более старой версии бот автоматически создаёт ветку `general` и продолжает разговор в ней.

## Что умеет (без изменений относительно v3)

- Текст, голосовые (локальный `faster-whisper`), фото — привязаны к активной ветке (файлы кладутся в её рабочую директорию).
- Конвертация Markdown → Telegram MarkdownV2, безопасная разбивка длинных сообщений по границам блоков кода.
- Живой индикатор «печатает…», пока Claude думает.
- Whitelist по `ALLOWED_USER_IDS`.

## Файлы

Как в предыдущих версиях, плюс `skills.json` — файл с пресетами скиллов, путь к нему настраивается через `SKILLS_FILE` в `.env`.

## Установка

Как в v1 (см. её README за подробностями). Дополнительно:

1. Положите `skills.json` рядом с `bot.py` (или укажите свой путь в `.env` через `SKILLS_FILE`).
2. Опционально задайте `CLAUDE_PERSONA` в `.env` — это дефолтный стиль для новых веток (для конкретной ветки его всегда можно переопределить командой `/style`).

## Обновление с более старой версии

Замените `bot.py` (и добавьте `skills.json`, если его не было), перезапустите сервис:

```
systemctl restart claude-bridge
```

Старая история разговора не теряется — она автоматически попадает в ветку `general`.
