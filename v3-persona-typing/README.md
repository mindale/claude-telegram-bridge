# v3 — дружеский тон, живой индикатор «печатает…», надёжная разбивка сообщений

Три независимых улучшения поверх [v2](../v2-markdown-fix), сделанные по одному запросу пользователя и одному найденному в процессе багу.

## Что изменилось относительно v2

### 1. Дружеский, человеческий тон общения

Раньше Claude отвечал в дефолтном стиле Claude Code (по существу, иногда суховато). Добавлена системная инструкция (`DEFAULT_PERSONA`), которая просит Claude:

- общаться как близкий друг в переписке, а не как ассистент техподдержки;
- писать живо, с обычными разговорными фразами, юмором и эмоциями;
- не форматировать ответы как markdown-документ (без `#`-заголовков, `**жирного**`, длинных списков и разделителей) — просто нормальный связный текст абзацами, как в обычной переписке.

Инструкция передаётся в Claude через `--append-system-prompt` при каждом вызове. Переопределяется переменной `CLAUDE_PERSONA` в `.env`, если нужен другой тон.

### 2. Живой индикатор «печатает…»

В v1/v2 статус "печатает..." отправлялся один раз перед вызовом Claude и гас через ~5 секунд по ограничению самого Telegram — если ответ готовился дольше (частый случай для сложных запросов), пользователь долго смотрел на пустой чат без индикации.

Добавлен класс `TypingIndicator` — асинхронный контекст-менеджер, который держит фоновую задачу, обновляющую статус «печатает…» каждые 4 секунды, пока не придёт ответ:

```python
async with TypingIndicator(chat_id):
    reply = await run_claude(chat_id, text)
```

Индикатор виден в Telegram непрерывно, сколько бы Claude ни думал.

### 3. Исправлена разбивка длинных сообщений (баг из v2)

В v2 разбивка на части шла по числу символов без учёта структуры. Если разрез попадал внутрь блока кода (``` ```), после конвертации в MarkdownV2 кусок получался с незакрытым тройным бэктиком — Telegram отклонял его, и весь ответ откатывался на сырой текст (видны были решётки и звёздочки).

Добавлена функция `split_markdown_blocks()`, которая:

- разбирает текст на блоки, отслеживая, где начинается и заканчивается ``` ```-блок кода;
- никогда не разрезает блок кода посередине — он всегда попадает в чанк целиком (или, в крайнем случае гигантского блока, режется построчно как последний резерв);
- собирает обычные абзацы в чанки под лимит длины Telegram.

Плюс отказоустойчивость стала точечной: если конкретный кусок всё же не отправился как MarkdownV2, обычным текстом заменяется **только он**, а не весь ответ целиком, как было раньше.

## Что умеет (не изменилось относительно v2)

- Текст, голосовые (локальный `faster-whisper`), фото.
- Одна сессия/история на Telegram-чат, `/reset` для сброса.
- Whitelist по `ALLOWED_USER_IDS`.
- Конвертация Markdown → Telegram MarkdownV2 через `telegramify-markdown`.

## Ограничение этой версии

Один Telegram-чат — всё ещё один непрерывный разговор с одним стилем на весь чат. Несколько параллельных веток разговора с разными стилями/скиллами добавлены в [v4](../v4-multichat).

## Файлы и установка

Структура и порядок установки не изменились относительно v1/v2 (см. README v1). Изменился только `bot.py` и опционально `CLAUDE_PERSONA` в `.env`.
